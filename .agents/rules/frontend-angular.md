# Frontend Rules (Angular)
*   **State:** Keep one SignalStore file per scope (`<name>.store.ts`). Components read store signals and call store methods. They never write state. Neither a component nor a store calls `HttpClient`. Never use `@ngrx/store` or a `BehaviorSubject` state service.
*   **Folders:** `shared/` groups by intent (`storage/`, `i18n/`). A feature has a module-like name, its feature-wide files at the root, and one folder per use case (`machines/dashboard/`). Never create technical folders (`services/`, `models/`, `components/`, `utils/`).
    *   **Nesting:** A component gets its own folder with its template, its `.utils.ts`, and its spec. When 2 or more files or components of a folder serve one narrower sub-intent, move them into a sub-folder named after it (`shared/time/pickers/`). Never create a sub-folder for one file. A component folder also holds the files named after the component: its form schema (`<name>-form-schema.ts`) and its specs. Never put them in the parent folder. `folder-layout.spec.ts` checks the form schema and `.utils.ts` placement. No tool checks the sub-intent.
    *   **Aliases:** Use `@app/`, `@shared/`, and one `@<feature>/` per feature folder directly under `app/` (no `features/` folder). Add the alias to `tsconfig.json` and the `@app/<feature>/*` ban to ESLint with the feature. ESLint bans `../` imports.
*   **Utils:** Put the pure functions, mappings, label maps, and column declarations of a component or a store in `<name>.utils.ts` next to it, so the class keeps only its signals, inputs, outputs, and handlers. Never put them in a standalone feature file (e.g., `machine-labels.ts`). A helper without a feature type belongs in the `shared/` folder of its intent (e.g., `shared/grid/`). No tool checks it.
*   **Scope by Provider:** Global: `providedIn: 'root'`, only in `shared/`. Feature: `providers` on the lazy feature route. Local: `providers` on the component. Choose the narrowest scope that all readers share.
*   **Persistence:** Use only `withStorageSync` and `BROWSER_STORAGE`. Never use `localStorage` directly.
*   **Runtime Config:** `config.json` is public. `parseAppConfig` validates it with a `zod/mini` schema. Put only values that every visitor may see in it. Never add a secret, a key (except the PrimeUI license key below), or an internal host name.
    *   **PrimeUI License:** The PrimeUI license key is the one key in `config.json`: PrimeNG checks it in the browser, so it is public by design. The SPA host reads it from `PRIMEUI_LICENSE_KEY` (Compose, `.env`), and `createAppConfig` passes it to `providePrimeNG`. Never commit it and never build it into the bundle.
*   **DI:** Inject with `inject()` only. Import each class or token that DI reads at run time as a value. Use `import type` only for pure types (ESLint `prefer-inject`, `consistent-type-imports`).
*   **Tests:** Test only logic with branching or processing (services, stores, store features, serializers, pipes, `.utils.ts` functions, component methods). Never test rendering, templates, or the DOM. Test a component method through the class. A route flow test is the one exception: it navigates with `RouterTestingHarness` over the real routes and providers, answers HTTP with `HttpTestingController`, and asserts only the requests, the store state, and the active route component, never the DOM. No tool checks it. `ng generate component` skips the spec (`angular.json`); add one by hand only for such logic.
*   **Server Data:** A feature API service (`<feature>-api.ts`) owns every `HttpClient` call and returns Observables. A shared one is `providedIn: 'root'`; a feature one is provided on the feature route or the action host. Stores read with `rxResource` over the service and write with `rxMethod`. Never use `httpResource`. ESLint checks both.
*   **Styling:** Define colors and tokens only in `healthyfac-preset.ts`. Templates use Tailwind token utilities (`bg-surface-*`, `text-primary`). Never write a hex color in a component.
    *   **Plain CSS:** Use plain CSS, no SCSS. A component gets no style file by default. Add one (`--style css`) only when utilities and tokens are not enough. Tailwind setup lives only in `src/styles.css`.
    *   **`@apply`:** Use it only for more than 16 utilities on one element (component CSS with `@reference` to `styles.css`), or for a set that appears in 3 or more places or must look the same (`@layer components` in `styles.css`, `hf-` prefix). Never use it for a short set such as `flex flex-col`. No tool checks it.
    *   **Component Size:** Change a PrimeNG component size only through its component tokens in `healthyfac-preset.ts` (e.g., `components.datepicker`), never with component CSS. No tool checks it.
*   **Buttons:** Use the `pButton` directive on a native `<button>`; never the deprecated `p-button` component (ESLint checks the import).
*   **Text:** Write every visible string as a translation key in all files under `public/i18n/`. Write each key segment in capitalized snake case (`ERRORS.HTTP.NOT_FOUND`). The keys inside `PRIMENG` keep the PrimeNG names.
*   **Time:** Use Temporal from `@shared/time/temporal` for every date and time value. Use `Instant` for past moments, `PlainDateTime` plus an IANA zone or `ZonedDateTime` for planned local times, and `PlainDate` for dates. Read the current time only through `CLOCK`. `Date` appears only inside `shared/time/` (the PrimeNG boundary).
*   **Forms:** Use Signal Forms only (`form()`, `[formField]`). A PrimeNG control that needs another value type gets a `FormValueControl` wrapper in the `shared/` folder of its intent. Use `ngModel` only inside such a wrapper, or for one standalone control outside a form (e.g., the shell language select). Validate a form with a `zod/mini` schema through `validateStandardSchema`. Put a schema that several features share in the `shared/` folder of its intent. ESLint blocks the full `zod` import.
    *   **Save:** **Save** is disabled while the form is invalid or unchanged, with a tooltip that gives the reason. Detect a change with `hasFormChanges(schema, initial, current)` (`shared/forms/`); never write a compare function per form.
    *   **Invalid State:** A field shows its invalid state (red border, messages) only after the user touched it (`isFieldInvalid`, `shared/forms/`). Signal Forms writes `invalid` into a control, so a PrimeNG control on `[formField]` cannot bind `[invalid]`: set `data-hf-calm` on it (`styles.css` resets the invalid border). No tool checks it.
    *   **One Schema:** The form and the action payload validate with one `zod/mini` schema; the payload uses its `partial`. The field limits mirror the backend constants in one `<feature>-limits.ts`. No tool checks it.
*   **Loading:** Show a loading state in the place of the data and keep the surrounding structure. A grid shows `min(limit, 10)` rows of `p-skeleton` and never `[loading]`. A dialog or a form shows `LoadingSpinner`. A select shows `[loading]` while its options load. An empty result shows `EmptyState` across the free body height. No tool checks it.
*   **Grids:** A grid store composes `withGridState` (`shared/grid/`): a filter or sort change resets `offset` to 0. Map the sort with `toSortOrder` and `toSortDirection`.
    *   **Filters:** A column filter applies only on **Apply** and resets on **Clear**. Bind `[filters]` to the store state, so a closed menu drops its pending value. Never call `filterCallback` in a `#filter` template.
    *   **Requests:** Build each filter body with the `shared/grid/` builders. An empty filter stays out of the request. A date range is the half-open UTC range of the local dates in `CLOCK.timeZoneId()`. No tool checks the grid rules.
*   **Overlays:** Set `appendTo="body"` on every overlay (`p-select`, `p-datepicker`, `p-menu`, `p-popover`), so no scroll boundary clips it. Inside a column filter menu, use `appendTo="self"`: the menu is already on `body` and closes on a click in another `body` overlay. An action opens in a modal `ActionDialog`. No tool checks it.
*   **Confirmations:** A confirm dialog sets `rejectButtonProps: { severity: 'secondary' }`, and a destructive accept uses `severity: 'danger'`. No tool checks it.
*   **Zoneless and `OnPush`:** The view updates only from signals, event bindings, and the `async` pipe. Never set a plain field from `setTimeout` or a raw `subscribe` for the view. Use a signal (`toSignal`, a store). ESLint blocks `zone.js`, `NgZone`, `provideZoneChangeDetection`, and `ChangeDetectionStrategy.Eager`.
*   **Authentication:** Read the session only through `AuthStore` (`shared/security/`). Never import `keycloak-js` elsewhere (ESLint), and never store, log, or expose a token. Add `canActivate: [authGuard]` to each protected route; a public route has no guard.
*   **Smart and Dumb:** Only a route page (`*-page.ts`) and an action host (`*-host.ts`) inject stores. Every other component uses only `input()`, `output()`, and `model()`, and injects no store and no `HttpClient`. Debounce, query building, and toasts live in the stores. Exception: the shared `RichTextEditor` (`shared/rich-text/`) is a form control with its own image upload flow. It may inject `RichTextImageLinks` and `MessageService` and show its own image toasts. It still injects no store and no `HttpClient`. No tool checks it. ESLint bans `*.store` imports elsewhere (routes, route resolvers, route guards, `layout/`, `shared/`, and the root files are exempt).
*   **Layout:** Target screens from 1024 × 600 CSS pixels. Set `h-dvh` once, on `hf-root`. Every flex item on the chain down to a scroll boundary gets `min-h-0` (vertical) or `min-w-0` (horizontal). Fixed parts get `flex-none`, and parts that fill the space get `flex-1`. Each region has one scroll boundary: the grid scrolls through `scrollHeight="flex"` and has no scroll wrapper. Use `overflow-hidden` only where clipping is the goal. Every `@Component` sets its display in `host: { class }` (ESLint checks it). Use `rem`, and `px` only for borders. No tool checks `min-h-0`, `min-w-0`, or `px`.
*   **Route Params:** The router binds route params to inputs (`withComponentInputBinding()`). A route page reads a param only as an `input()` with the param name, and passes it to its store through a store method. Never inject `ActivatedRoute`: a store on route `providers` gets the root route. Name page inputs only after route params, because the router also binds query params and `data` keys. ESLint checks the `ActivatedRoute` import.
*   **Generation:** Use `ng generate` for components, services, guards, and pipes.
*   **Enforcement:** Prettier and ESLint, run by the Stop hook. ESLint allows `HttpClient` only in `*-api.ts`, specs, and `shared/http/`, and bans `httpResource` everywhere. `translation-files.spec.ts` checks the translation keys.
