# Web Layer Rules
*   **API Paradigm:** Use Minimal APIs only, never MVC controllers (architecture tests check it).
*   **API Contracts:** Bind the Application request in the endpoint and return the Application response. Define no Web request or response records and no mapping, except for server-owned values.
    *   **Server-Owned Values:** When the Application request holds a value from the server (e.g., `CompanyId` from the token), define a Web request record without it, with the name of the Application request, in its own file in the Web feature folder. In the same file, add a static class `<UseCase>RequestExtensions` with an `extension` block method `ToApplicationRequest(<server values>)`. The endpoint binds the Web request and calls it; it never builds the Application request itself. Never use `[JsonIgnore]` for this. The response stays the Application response.
    *   **Application Alias:** Name the Application request through a `using` alias with the prefix `Application` (e.g., `using ApplicationCreateEmployeeInviteRequest = HealthyFac.Core.Application.Employees.CreateEmployeeInvite.CreateEmployeeInviteRequest;`) in each file that uses it. Put the aliases after all other `using` directives. Never write its namespace path in code. Above 120 characters, break after `=` and indent the type by 4 spaces.
*   **Endpoint Grouping:** Put all endpoints of one feature in one `<Feature>Endpoints.cs` file with one `Map<Feature>Endpoints` method and its routes class next to it (e.g., `EmployeeInviteRoutes`). Write each route handler as a private static method, mapped as a method group. Never create a file or a folder per route.
*   **Handler Injection:** Inject `IRequestHandler<TRequest, TResponse>`, or `IRequestHandler<TRequest>` for a use case without a result, into the delegate. Never inject a mediator or a dispatcher.
*   **Request Logging:** Call `UseSerilogRequestLogging()` in `UseApiPipeline` before `UseSharedExceptionHandling`, so the log records the status code that the client receives. Never log with `Console` or `Debug`.
*   **Middleware:** Implement `IMiddleware`, with dependencies in a primary constructor. Never write convention-based middleware (a `RequestDelegate next` constructor; architecture tests check it) or inline `app.Use(async (context, next) => ...)` lambdas.
    *   **Registration:** Register it next to the services of its concern, with the lifetime of its shortest-lived dependency: `AddSingleton` when all are singletons, `AddScoped` when one is scoped. A singleton middleware never injects a scoped service.
    *   **Pipeline:** Add it with `UseMiddleware<TMiddleware>()` inside a `Use...` method. A missing registration fails at the first request, so the pipeline tests cover it.
*   **Health Endpoints:** Serve `/health`, `/health/ready`, and `/hc` only on the health port (`HealthEndpoints:Port`). Call `UseSharedHealthChecks()` as the first middleware: it compares the local port of the connection. Never use `RequireHost`, because a client sets the `Host` header. Never publish the health port through the gateway or a public load balancer. The gateway forwards only versioned API paths (e.g., `/api/core/v1/...`).
*   **Public URLs:** Use the logical names `api.<domain>` (gateway API routes), `auth.<domain>` (Keycloak, the token issuer), and `app.<domain>` (the web app) for the issuer, redirect URIs, email links, and CORS origins. Never use `localhost` in a public URL. Every public URL uses HTTPS; the gateway ends TLS with the mkcert certificate in `docker/certs/` (never committed). Development tools (admin consoles, Mailpit, Grafana, health ports) stay on `localhost`. Each gateway route matches its name with YARP `Match.Hosts`. Set the names per environment (`appsettings.Development.json`, Compose), never in `appsettings.json`.
*   **CORS:** The gateway owns CORS: `AddSharedCors`, `UseSharedCors()` before `UseAuthentication`, and `"CorsPolicy"` on each YARP route that the web app calls. A service behind the gateway keeps `Cors:IsEnabled = false`, because two `Access-Control-Allow-Origin` writers make the browser reject the response. Keycloak answers CORS for its own routes from the client `webOrigins`.
*   **Fallback Policy:** Every service that maps endpoints, and the gateway, call `SetAuthenticatedFallbackPolicy()`. A service without endpoints registers no authentication and no authorization. Mark each public endpoint with `AllowAnonymous()`, and each public YARP route with `"AuthorizationPolicy": "anonymous"`.
*   **Permissions:** Define them in one `<Service>Permissions` class in the Web `Authorization/` folder. Each feature gets a nested static class with a `const string` per permission and a `public static readonly FrozenSet<string> All` collection expression. The service `All` spreads every feature `All`. Register the policies once with `AddPermissionPolicies(<Service>Permissions.All)`. Reference `<Service>Permissions.<Feature>.<Action>`; never list permission names inline.
    *   **Keycloak Model:** Each permission is a client role of the API client of the service, which holds permissions only. A job role (`supervisor`) is a composite realm role. The policies read the flat `permissions` claim (`KeycloakClaimTypes.Permissions`). Never tell a permission from a role by its name format. Keep each permission name unique across all APIs, because the claim is flat and an exchanged token also carries the permissions of the calling API (`docs/architecture.md`).
    *   **Service Clients:** Give each deployable unit its own client and secret, with `fullScopeAllowed: false`, one service role with only the permissions its calls need, and one optional client scope `{service}-{name}` per downstream scope. Split a component into its own client only when it runs in its own process with its own secret. Never give a service role to a person, or a job role to a service account.
*   **Options Validation:** Validate every options class with an `AbstractValidator<TOptions>` at startup through `AddValidatedOptions<TOptions, TValidator>()` (`.ValidateOnStart()`). Never check configuration ad hoc.
*   **Registration Grouping:** Put registrations in `ConfigureServices.cs` extension classes, never in `Program.cs`, behind one high-level method (e.g., `AddApiServices`). Group the calls of one concern into a private `Add...` method named after it (`AddApiObservability`, `AddApiSecurity`) when the concern needs 3 or more calls; leave 1 or 2 calls in the caller. Apply the same to `UseApiPipeline` (by pipeline stage) and `MapApiEndpoints` (by feature). Never split by line count.
*   **Database Initialization:** Infrastructure provides an `IServiceProvider` extension (e.g., `InitializeDatabaseAsync`) that `Program.cs` calls after the host builds. It resolves the service initializer (e.g., `ICoreDbInitializer`) in a new scope and runs `ApplyDatabaseStructureAsync` (migrations, only in Development; other environments migrate in a deployment step), `SeedRequiredDataAsync`, and `SeedOptionalDataAsync` when configuration enables it.
